# 工具定义被上游拒绝导致"无法发出请求" — 根因与修复 · 2026-10-13

dsh-mcp-manager v0.1.0(commit `b09add4` 安装态)

## 1. 用户可见症状

在 DSH 中启用本插件后,**任何一次对话都发不出去**:模型还没开始回答就报错,提示与"工具"有关。

- wb-pool 路由:
  ```
  503 {"code":"no_healthy_account","message":"{\"code\":11129,
       \"msg\":\"invalid function call parameters\",
       \"extError\":{\"code\":\"invalid_function_parameters\"...
       \"displayMsg\":{\"zh\":\"工具定义不符合模型要求,请新建任务后重试。\",
                      \"en\":\"The tool definition does not meet the model requirements.\"}}"}
  ```
- workbuddy-ai 路由:`400 请求参数不符合当前模型要求,请调整后重试。`

关键点:这是**整个请求被拒**,不是某个工具调用失败——所以表现为"开不了口",而不是"某个工具用不了"。

## 2. 根因

`lib/tools-bridge.js` 中 `mcp_manager_credential` 的参数 schema 把 `oneOf` 当枚举用:

```js
op: { type: 'string', oneOf: ['get', 'set'] }   // ✗ 非法 JSON Schema
```

JSON Schema 里 `oneOf` / `anyOf` / `allOf` 的值必须是**schema 数组**,不能是字符串数组。上游按 JSON Schema 校验每个 tool 的 `parameters`,一个不合法的定义就导致整批 tools 被拒 → 请求 503/400。枚举的正确关键字是 `enum`。

全仓库 `oneOf|anyOf|allOf` 仅此一处(已核实)。

## 3. 隔离实验(单变量,直连 wb-pool)

用 `global:deepseek-v4.1-flash` 逐条构造 tools 数组,每次只改一个变量:

| 用例 | tools | 结果 |
|---|---|---|
| A | 无 tools | HTTP 200 ✅ |
| B | 一个普通 tool | HTTP 200 ✅ |
| C | `op: {type:'string', oneOf:['get','set']}` | **HTTP 503 invalid function call parameters** ❌ |
| D | `op: {type:'string', enum:['get','set']}` | HTTP 200 ✅ |
| E | 插件实际发出的 7 个 `mcp_manager_*` 定义(修复前) | **HTTP 503** ❌ 复现 |
| F | 同上,仅把 `op.oneOf` 换成 `op.enum` | HTTP 200 ✅ |

C 与 D 只差一个关键字 → 根因锁定;E 复现线上故障,F 证明修复有效。

旁证(会话日志 `request/header` 与 `turn/end`):带 `mcp_manager_*` 的请求 tools 数为 144,全部以 `INVALID_REQUEST` 结束;不含这 7 个工具的请求(137)正常返回。

## 4. 修复

```diff
- op: { type: 'string', oneOf: ['get', 'set'] }
+ op: { type: 'string', enum: ['get', 'set'] }
```

一处一行,无其他改动。

## 5. 回归测试

新增 `test/tool-schema.test.mjs`:

1. 通用守卫:递归遍历每个工具的 `parameters`,断言 `oneOf/anyOf/allOf/prefixItems` 是**非空 schema 数组**、`enum/required` 是数组、`type` 是字符串或字符串数组、`properties` 是对象。修复前该测试失败并直接指出
   `mcp_manager_credential.properties.op.oneOf[0]: expected a schema object, got "get"`。
2. 定点断言:`op.enum === ['get','set']` 且 `op.oneOf === undefined`。

先写测试→跑出失败→再改代码(已按此顺序执行)。

## 8. 教训

工具定义里的 schema 是**发给上游模型的**契约,不是内部数据。关键字用错不会在本地报错(DSH 不校验),只会在真实请求时被上游整体拒绝,且错误信息只说"工具定义不符合模型要求",不指哪个工具——所以必须靠本地结构性校验兜底,这正是第 5 节测试的作用。
