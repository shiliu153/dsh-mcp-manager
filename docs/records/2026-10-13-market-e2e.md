## 3. 需要凭据的远程条目 —— 不写入假凭据

```
$ node cli/mcp.js install ai.adadvisor/mcp-server --file <tmp>/cordis.patch.yml
registry: ai.adadvisor/mcp-server@1.0.1 (publisher ai.adadvisor)
runs:     https://api.adadvisor.ai/mcp
needs secret: Authorization — Bearer token (adv_sk_...). Get key: https://www.adadvisor.ai/...
--- entry to be written ---
- insert:
    - id: mcp-adadvisor
      name: '@deepseek-ai/dsh-mcp-client'
      disabled: false
      config:
        failOnStartupError: true
        serverName: adadvisor
        transport: streamable-http
        url: https://api.adadvisor.ai/mcp
```

落盘后读回:

```
$ node cli/mcp.js install ai.adadvisor/mcp-server --file <tmp>/cordis.patch.yml --yes --no-probe
written (backup: ...\cordis.patch.yml.bak)

$ node cli/mcp.js show mcp-advisor --file <tmp>/cordis.patch.yml
failOnStartupError: true
serverName: adadvisor
transport: streamable-http
url: https://api.adadvisor.ai/mcp
```

对整份文件搜索 `Authorization|API_KEY|Bearer` → **无命中**。秘密字段是被**省略**的,不是被填了占位值 —— patch 里不存在假凭据。装完后首次探测会返回 401,这是「还没补凭据」的准确信号。

**本次实测抓到一个真实缺陷并已修复**:首次运行产出的是 `serverName: mcp-server` —— registry 里大量发布者把条目注册为 `…/mcp-server`,直接取名称段会得到一个什么都标识不了、且必然与下一位发布者碰撞的名字。修法:名称段为通用词(`mcp` / `server` / `mcp-server` / `server-mcp`)时回退到命名空间的反域名末段。`ai.adadvisor/mcp-server` → `adadvisor`。命名空间也取不到时保留 registry 原名(比凭空造一个 `server` 更诚实)。

## 6. 版本漂移

```
$ node cli/mcp.js install ai.ankimcp/anki-mcp-server --file <tmp>/cordis.patch.yml --yes --no-probe
written (backup: ...)

$ node cli/mcp.js search anki --file <tmp>/cordis.patch.yml
ai.ankimcp/anki-mcp-server@0.27.0  [ai.ankimcp]
  serverName: anki-mcp-server
  runs: npx -y @ankimcp/anki-mcp-server@0.27.0
  installed as mcp-anki-mcp-server (current)

# 把条目里的钉版本回退一位
$ (Get-Content patch) -replace '@ankimcp/anki-mcp-server@0\.27\.0','@ankimcp/anki-mcp-server@0.26.0' | Set-Content patch
$ node cli/mcp.js search anki --file <tmp>/cordis.patch.yml
  installed as mcp-anki-mcp-server (behind)
```

`current` → 回退一位 → `behind`。

**未钉版本的条目不下结论**:`add` 路径写的 `npx -y <pkg>` 没有版本锚点,市场报「版本未钉住,无法比对」而不是假装已是最新。由 `test/drift.test.mjs` 与 `test/plugin-tools.test.mjs`(断言 `cannot be compared`)覆盖。

**已安装识别忽略版本钉**:这一点是实施期发现的硬约束 —— 漂移检测要处理的场景恰恰是版本不同(`@0.27.0` vs `@0.28.0`),逐字比较 `args` 永远不相等,「已安装」与「漂移」会互相排斥。身份比较改为先剥掉版本钉(npm 第二个 `@`、pypi `==`、oci tag)再比。

**去重不得吞掉已匹配的那一行**:`deriveMarketServerName` 拿「已登记的全部 serverName」去重,而该服务器自己的行就在这个列表里 —— 天真实现会把候选名推成 `name-2`,面板认不出已安装,用户点「安装」会真的装出第二份。修法:先按执行面(与名字无关)找出已匹配行,再把它排除出去重集合。

## 7. 官方 registry 的实测延迟(影响超时取值)

对真实 registry 连续请求:

| 请求 | 耗时 | 结果 |
|---|---|---|
| `GET /v0/ping` | ~1.0s | 200 |
| `GET /v0/servers?search=anki&limit=20&version=latest` | 17.6s | 200 |
| 同上 | 4.3s | **500** |
| 同上 | 1.2s | 200 |
| 同上 | 30.1s | 200 |

`/v0/servers?search=…` 的延迟在 1.2s–30s 之间剧烈波动,并偶发 500。原先定的 8s 超时会让功能在真实环境下基本不可用(首次 CLI 冒烟就是 `registry timeout after 8000ms`)。**改为 30s**,并对 5xx 保留一次重试(实测该端点确实会偶发 500)。`timeoutMs` 仍是可注入参数。

## 8. 面板验收时暴露的探测缺陷(已修)

面板首次实测时报:

```
探测失败：server exited early (code 1)
```

调查后确认这**不是市场的问题,而是三个叠加的问题**,其中两个在我们的代码里。

### 8.1 registry 的元数据是错的(不是我们的 bug)

`@ankimcp/anki-mcp-server` **不是 stdio 服务器**。直接运行市场写下的那条命令:

```
$ npx -y @ankimcp/anki-mcp-server@0.27.0
╔════════════════════════════════════════════════════════════════╗
║                  AnkiMCP HTTP Server v0.27.0                   ║
╚════════════════════════════════════════════════════════════════╝
🚀 Server running on: http://127.0.0.1:3000
   • Port:  3000 (override: --port 8080)
```

它打印一个横幅、绑定 `127.0.0.1:3000`、**从不读取 stdin**。而 registry 条目声明的是:

```json
"packages": [{ "registryType": "npm", "identifier": "@ankimcp/anki-mcp-server",
               "version": "0.27.0", "transport": { "type": "stdio" } }]
```

**registry 把它的传输方式标错了。** 市场只能照抄 registry 的声明,没有任何信号能识别这种错误。同类条目在 registry 里很常见(大量发布者注册为 `…/mcp-server`)。

### 8.2 探测泄漏整棵进程树(我们的 bug)

`child.kill()` 只杀直接子进程。Windows 上 `npx` 解析为 `npx.cmd`,于是 `spawnShape` 把命令包成 `cmd.exe /c "…npx.cmd"`,**直接子进程是那层 cmd.exe,真正的服务器是孙进程**,`child.kill()` 杀不到它。

隔离复现(临时夹具,`cmd.exe /c shim.cmd` → node 夹具):

```
parent called child.kill() and is exiting now
ORPHAN ALIVE: PID 37928 (node) -- survived child.kill()
```

**这条因果链正好解释了用户看到的报错**:

1. 第一次探测:服务器启动、占住 3000、忽略 stdin → 探测超时 → 只杀掉 cmd.exe → **孤儿服务器继续占着 3000**;
2. 第二次探测:服务器尝试绑定 3000 → `EADDRINUSE` → 退出 1 → 探测报 **`server exited early (code 1)`** —— 一个把真实原因藏起来的消息。

修法:`lib/subprocess.js` 新增 `killTree()`,Windows 上 `taskkill /pid <pid> /T /F`。

**第一次修法仍然是错的,值得记下来**:最初用异步 `spawn('taskkill', …)`,树**依旧泄漏** —— 调用方在同一 tick 内就报结果并退出(`cli/mcp.js` 结尾是 `process.exit`),kill 还没落地。改成同步 `spawnSync` 后修复。实测同步 `taskkill /T /F` 一次干掉整棵树 5 个进程:

```
SUCCESS: The process with PID 33980 (child process of PID 5256) has been terminated.
SUCCESS: The process with PID 28188 (child process of PID 5256) has been terminated.
SUCCESS: The process with PID 5256 (child process of PID 20588) has been terminated.
```

修复后对真实 anki 条目复测:无孤儿、3000 端口释放、**第二次探测拿到的是真实原因**(超时 + 提示)而不是 `code 1`。

### 8.3 探测把证据丢掉了(我们的 bug)

横幅打在 **stdout** 上,而 `probeStdio` 只把 stdout 当 JSON-RPC 逐行解析、非 JSON 的行直接丢弃,只保留 stderr 作为 `detail`;而 `detail` 又没被路由和工具向上传递。于是唯一能说明问题的那一行,谁也没看见。

修法:
- 非 JSON 的 stdout 行收进 `stdoutNoise`,`detail` 由 stdout + stderr 两段拼成;
- 新增 `hint`:输出里出现 http(s) 端点却始终没有 stdio 应答时,提示「这个包可能不是 stdio 服务器,registry 条目的传输方式可能标错了」(措辞是提示,不是断言 —— 我们看得到输出,看不到包的意图);
- `detail` 与 `hint` 现在贯通四个面:面板 `probeText`、面板路由、`mcp_manager_probe`、CLI `probe`。

修复后的实际输出:

```
$ node cli/mcp.js probe --id mcp-anki-mcp-server --file <tmp>/cordis.patch.yml --timeout 10
FAIL  mcp-anki-mcp-server (stdio): stdio probe timed out after 10000ms
  hint: the process printed http://127.0.0.1:3000 and never answered on stdio — this package may
        not be a stdio server, so the registry entry may have mislabelled its transport
  | MCP streamable-http transport ready (stateless, self-mount disabled — a controller owns the route)
  | Mapped {/, POST} route
  | Nest application successfully started
```

新增测试:`test/probe.test.mjs` 4 条(横幅保留、hint 生成、普通崩溃不产生 hint、进程树被杀 —— 后者用 `cmd.exe` shim 复现并断言孙进程真的消失,Windows 之外跳过),`test/client.test.mjs` 1 条(hint 与 detail 贯通到面板)。

### 8.4 对这条 registry 条目的结论

`ai.ankimcp/anki-mcp-server` **作为 stdio 条目无法使用**。它是个需要单独运行、且依赖 AnkiConnect 的本地 HTTP 服务器。用户机器上的 `mcp-anki-mcp-server` 条目已被 DSH 置为 disabled,不影响其他服务器。
