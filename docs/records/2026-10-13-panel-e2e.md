## 2. 过程中发现并修复的三个缺陷

### 2.1 工具定义里的 `oneOf`（既有，2026-10-13 上午）

`mcp_manager_credential` 的 `op: { oneOf: ['get','set'] }` 不是合法 JSON Schema（`oneOf` 必须是 schema 数组）。上游校验 tool 定义，一个坏定义就拒掉**整个请求**，所以症状是"开不了口"而不是"某个工具用不了"。已改为 `enum`。

### 2.2 `lib/dump.js` 在 ESM 里调用 CJS `require`（既有，本次面板暴露）

```js
const res = IS_ELECTRON ? require('node:path').join(...) : '.../app.asar';
```

`IS_ELECTRON` 分支**只在 harness 内部**走。普通 node（CLI、全部单测、所有手工检查）走的是硬编码那条，所以这个 bug 从未被碰到——**所有读 patch 文件的宿主工具在真实 app 里都是坏的**，症状 `ERROR: require is not defined`。被 2.1 的 schema bug 盖住了。已改为 `import path from 'node:path'`，并加 `test/esm-hygiene.test.mjs` 扫描 `lib/**/*.js` 与 `index.js` 禁止裸 `require(`。

### 2.3 面板开关用了不存在的主题 token（本次引入，用户发现）

开关渲染成一个没有 thumb 的空药丸，且四个 token 里有三个是**猜的**：

```
--dsw-alias-text-primary      ✗ 不存在
--dsw-alias-text-secondary    ✗ 不存在
--dsw-alias-border-secondary  ✗ 不存在
--dsw-alias-brand-primary     ✓ 存在
```

未知自定义属性会让声明在 computed-value 阶段失效，于是 `border` 与 `color` **静默消失**：关闭态连边框都没有，开启态只剩一块纯品牌色——就是用户看到的"一片黑"。

修法照官方要求：从宿主 `Switch.module.css` 抄 track 与 thumb 并改用本插件前缀，状态键改为 `aria-checked`（不再自造 `data-on`），其余 token 全部换成宿主真实词表（`--dsw-alias-label-*`、`--dsw-alias-border-l*`）。

新增两道守卫：`client.js` 里每个 `var(--dsw-*)` 引用都必须存在于一份从已装主题包里读出的白名单；渲染断言开关必须带 `role=switch`、`aria-checked` 与 thumb 子节点。

**教训**：这三处都属于"本地怎么测都不报错、只在真实环境里静默出错"。2.1 与 2.3 都是静默失效，2.2 只在 Electron 分支上炸。共同点是没有一条测试覆盖"真实环境的那条路径"——现在三条都有了守卫。
